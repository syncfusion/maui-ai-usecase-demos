# INTENT — SkyBook for .NET MAUI

## Why this exists
`flight-booking/client/react` is the reference **SkyBook** client: a chat-driven, three-stage flight-booking
experience (Search → Results → Confirmation) whose booking screens are *generated by an AI agent* and rendered
through the **A2UI v0.9** protocol with Syncfusion EJ2 components. This harness defines the work to deliver the
same product as a **.NET 10 MAUI** app that renders the agent's surfaces with **`Syncfusion.Maui.A2UI`**.

## Goal
A MAUI app that is **indistinguishable from the React client in behaviour and layout intent**, talking to the
**same Python agent** over the **same A2A JSON-RPC endpoint**.

## Success criteria (the definition of done)
| # | Criterion | How it is checked |
|---|-----------|-------------------|
| S1 | Targets **.NET 10** (`net10.0-*`), uses `Syncfusion.Maui.A2UI` for all surface rendering | csproj + Android build in `harness/verify.sh` |
| S2 | Welcome screen: hero, journey strip, 3 stage cards, "Ask SkyBook" input | manual parity checklist (PLAN §6) |
| S3 | Chat screen: header (avatar, Online, Clear, current-step pill), conversation, typing indicator, stepper, surface pane, placeholder workspace | manual parity checklist |
| S4 | Outgoing agent text is **byte-identical** to React (history block, trip-context block, "Book now" instruction, stage-3 intent) | `SkyBook.Core.Tests` |
| S5 | Chat bubble text for surface actions equals React's `summarizeAction` | `SkyBook.Core.Tests` |
| S6 | Agent envelope sanitising (`sanitizeEnvelope`) and `/_explanation` extraction behave as React | `SkyBook.Core.Tests` |
| S7 | Search → Results → Book-now → Confirmation works end-to-end against the agent | manual E2E (needs LLM key + device) |
| S8 | Build is warning-free (`TreatWarningsAsErrors`) | `harness/verify.sh` |

## In scope
* MAUI client (`src/SkyBook.Maui`), platform-neutral logic (`src/SkyBook.Core`), unit tests.
* MAUI-catalog designs for the agent (`agent/.../designs_maui`) and an opt-in switch
  (`FLIGHT_BOOKING_CLIENT=maui`) — the React client and its designs are **not modified**.

## Out of scope
* Changing the agent's protocol, models, providers or the React client.
* Pixel-perfect CSS reproduction (blur/backdrop filters, web fonts). Visual *intent* (colours, gradients, radii,
  hierarchy, copy) is preserved; web-only effects are approximated.
* Store packaging, signing, CI/CD for device builds.

## Non-negotiable constraints
1. **Same wording, same flow.** Prompts, labels, stage copy and fallbacks are copied from `App.tsx`, not re-invented.
2. **Agent is the source of truth for surfaces.** The client never hard-codes a booking screen.
3. **Secrets never in source.** Syncfusion license key and agent URL come from `AppConfig` / environment.
4. **Accessible by default** (semantic descriptions, `AutomationId`s, keyboard-sendable inputs).

## Known divergences (accepted, documented)
| Topic | React | MAUI | Reason |
|-------|-------|------|--------|
| Component catalog | `syncfusion-a2ui-catalog` (EJ2 names) | `syncfusion-maui` (`Sf*` names) | The MAUI package registers a different catalog; hence `designs_maui` |
| Flight selection | Per-row **Book now** command column | Tap row, then **Book now** button | `SfDataGrid` A2UI renderer has no command columns |
| Chat control | EJ2 `AIAssistView` | `SfAIAssistView` | Native equivalent |
| Welcome input | EJ2 TextArea | `Editor` | Native equivalent |
